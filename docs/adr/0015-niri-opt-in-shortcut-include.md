# ADR-0015: Extension Keyboard Shortcuts & Opt-In Niri KDL Projection

- **Status**: Accepted

## Context

Shilpo extensions contribute actions and global keybindings. On Wayland compositors (specifically Niri), global shortcuts cannot be intercepted safely via focused window key events without compositor authorization. Furthermore, Shilpo must remain compositor-neutral and must never directly mutate or edit the user's primary Niri configuration (`~/.config/niri/config.kdl`).

We required an architecture for extension keyboard shortcut declarations, layered resolution, and compositor projection that:
1. Permits extensions to declare recommended default keybindings targeting extension actions in manifest version `1`.
2. Resolves shortcuts across user config, built-in defaults, and extension defaults in strict precedence order (`user` > `built-in` > `extension`).
3. Projects resolved global shortcuts into an opt-in generated KDL include file (`$XDG_CONFIG_HOME/shilpo/generated/niri-keybindings.kdl`) without touching user configuration.
4. Invokes actions strictly through `ActionDispatcher` via safe argument boundaries (`spawn "shilpo" "action" "invoke" "<action-id>"`).
5. Emits structured diagnostics on conflicts or unavailable extensions while preserving dormant user bindings.

## Decision

### 1. Manifest Extension & Validation

We add `keyboard_shortcuts` array contribution type to `ExtensionManifest` (schema version `1`).
Each contribution specifies:
- `id`: unique contribution ID
- `name`: human-readable label
- `action`: target action contribution ID within the same manifest
- `default_binding`: optional shortcut specification (e.g. `"Super+Shift+W"`)

Shortcut specifications are validated and canonicalized into standard format (`Super`, `Ctrl`, `Alt`, `Shift` modifier order, uppercase key name). Invalid grammar, duplicate modifiers, or missing target actions fail manifest validation closed.

### 2. Layered Keybinding Resolution

`KeybindingManager` performs atomic resolution over candidate shortcuts using strict precedence:
1. `User`: `ShellConfig.keybindings` (`overrides.toml` / `config.toml`)
2. `BuiltinDefault`: Shilpo shell built-in default bindings (e.g., `Super+Space` for `builtin:toggle_overview`)
3. `ExtensionDefault`: Loaded extension recommended defaults

Disabling an action (`enabled = false`) explicitly suppresses defaults. Lower-precedence default conflicts emit structured diagnostics and are skipped rather than overriding higher-precedence bindings. Unknown extension action IDs in user configuration remain dormant and produce diagnostic warnings without invalidating user config files.

### 3. Opt-In Niri KDL Projection

Global keybindings are projected into `$XDG_CONFIG_HOME/shilpo/generated/niri-keybindings.kdl`. Users opt in by adding `include "shilpo/generated/niri-keybindings.kdl"` to their `~/.config/niri/config.kdl`.

Keybinding projections translate Shilpo modifier names (`Super`) to Niri modifier names (`Mod`) and bind to safe argument invocations:
```kdl
// Generated by Shilpo — do not edit manually
binds {
    "Mod+Shift+W" { spawn "shilpo" "action" "invoke" "ext:io.github.alice.weather/toggle-weather"; }
}
```

Writes use atomic tempfile creation and rename (`fs::rename`). If rendered KDL content is byte-identical to the existing file, writing and `niri msg action reload-config` are skipped. On failure, the last-good state is preserved intact.

### 4. Control Plane & Dispatch

`shilpo action invoke <action-id>` sends an IPC request over `org.shilpo.Shell` D-Bus (`InvokeAction`), which dispatches through `ActionDispatcher`. No new event or shortcut trigger action type was introduced.

## Consequences

- Global extension shortcuts function seamlessly under Niri via opt-in include without mutating user compositor configs.
- Keybinding conflicts and unavailable extensions emit clean, non-fatal diagnostics.
- Extension reload and unload dynamically reconcile keybindings without corrupting user overrides.
