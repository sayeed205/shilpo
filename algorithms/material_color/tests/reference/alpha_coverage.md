# Alpha reference supplement

These are bounded supplemental fixtures for 32-bit ARGB alpha handling. They were generated by
executing the pinned official TypeScript implementation, not by reproducing its color calculations.
They extend the finalized 2026 reference set without editing or regenerating any existing fixture.
See [`../alpha_provenance.md`](../alpha_provenance.md) for the source pin, preflight, hashes, and
repeatable command.

## Files and finite input matrix

| Fixture | Data rows | Coverage |
| --- | ---: | --- |
| `alpha_cases_2026.tsv` | 1,440 | 1,200 single-source schemes and 240 two-source CMF schemes. |
| `alpha_roles_2026.tsv` | 86,400 | Exactly the 60 accessor methods and order in the original dynamic-role manifest for every case. |
| `alpha_science_2026.tsv` | 30 | HCT and CAM16 observations for each raw ARGB seed. |

The five RGB triplets are black, gray, red, blue, and yellow. Each triplet is tested with alpha bytes
`00`, `01`, `7F`, `80`, `FE`, and `FF`, so RGB is held constant while opacity ranges from transparent
through opaque. Each single-source seed is sampled with all ten variants, both platforms (`phone`,
`watch`), light and dark modes, and contrast `0`. The CMF cases use same-RGB primary/secondary pairs:
the alpha-varied source is placed first and then second against the opaque version. They exercise
the multi-source branch in both positions across both platforms and modes. This is a finite sample,
not an exhaustive proof for all 32-bit ARGB values, source colors, or scheme options.

The `alpha_cases_2026.tsv` and `alpha_roles_2026.tsv` headers match the existing 2026 case and role
files. Case IDs use the distinct `A000001`…`A001440` range. Case metadata carries requested and
effective specs and the full unsigned source ARGB value(s). For multi-source cases, ARGB values are
pipe-separated in source order. Dynamic roles preserve the original category labels and
`0xAARRGGBB` uppercase output formatting.

## Observed alpha semantics

- `Hct.fromInt(argb).toInt()` retains the complete input ARGB integer, including alpha. The
  source-case ARGB is not silently made opaque or composited against a background.
- HCT hue/chroma/tone and CAM16 coordinates are calculated from RGB; for each tested RGB triplet,
  those values are identical across all six alpha inputs. `Hct.from(hue, chroma, tone)` resolves to
  an opaque color in these cases.
- `Cam16.fromInt` does not carry input alpha in its color coordinates; its `toInt()` result is
  opaque for all sampled seeds.
- Dynamic scheme source metadata retains the original HCT ARGB, whereas resolved dynamic-role
  outputs are opaque for these cases.
- `SchemeCmf` compares the first and second `Hct.toInt()` values as complete ARGB integers when
  choosing its tertiary palette. The same RGB with different alpha therefore takes the
  non-identical-source branch; the fixtures show differing tertiary key colors for the tested red,
  blue, and yellow examples. This is canonical source behavior, not a claim that alpha changes HCT
  coordinates.

Every case requests spec `2026`. The `effective_spec` column records canonical internal fallback:
CMF uses 2026; Neutral, Tonal Spot, Vibrant, and Expressive use 2025; Monochrome, Fidelity, Content,
Rainbow, and Fruit Salad use 2021. The supplement does not add separate legacy-spec matrices.
